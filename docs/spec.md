# 仕様書（MVP縮小版）

元の仕様書をもとに、MVPを「事業者が店舗を登録し、旅行者が一覧から選んでチャット・予約する」範囲に絞った版。
画面は **旅行者画面** と **事業者画面** の2つ。MVPは、本番環境に公開して実際に運用できる完成度を目指す。

- 【推測】：元の仕様書で推測とされていた内容
- 【提案】：今回の見直しで細部を補った案。実装前に確認する
- 【追記】：2026-10-15〜10-18 に書き加えた内容。前の決定を変えたところは、古い内容に取り消し線を引いている

---

## 1. ターゲット

### 旅行者（需要側）

- Lee Wei Ming（29歳）。シンガポール在住、IT勤務。初めての訪日で、関西を3泊4日で回る。
- 日本語はできず、英語は使える。中国語（簡体字）も読める【推測】。
- 情報は中華圏SNS、Instagram、Googleマップで集める。やりたいことは抹茶体験と地元の居酒屋。
- 旅程の骨格だけ決め、細部は前日や当日に決める【推測】。eSIMで常時オンライン【推測】。
- 「観光地化されていない本物の体験」を求める一方、失礼や場違いを恐れ、断られるのが怖くて店に入れない【推測】。

### 事業者（供給側）

- 宇治の小規模茶農家をはじめとする、体験・飲食店の小規模事業者。
- 60代夫婦と、手伝う30代の子どもの家族経営を想定【推測】。英語はできない。
- PCはほぼ使わず、スマホとメール・LINEは使う【推測】。受け入れは1日1〜2組、各2〜6名【推測】。
- 不安は、言葉、無断キャンセル、文化の違い【推測】。

## 2. 課題

- **旅行者**：検索しても観光バス向けの定番しか出てこない。気になる店を見つけても、英語の情報や予約手段がなく入れない。
- **事業者**：海外から問い合わせが来ても、英語で返せず予約の仕組みもないため、断るしかない。

MVPでは、元の仕様の「発見の断絶」と「受け入れの断絶」の2つを解く。「入店の断絶」は次フェーズに回す。

## 3. コンセプトと独自性【追記】

### コンセプト【追記】

**「観光する」から「その街の日常に少しだけ参加する」へ。**

- 旅行者は、特別に用意された観光プログラムだけでなく、その街の人が普段使っているお店、日常の過ごし方、店主との会話などを通じて地域を楽しむ。
- 事業者は、外国人観光客向けの新商品や特別なプログラムを必ずしも作る必要がない。通常の営業を維持したまま、対応できる範囲で旅行者を受け入れる。

### 独自性【追記】

独自性の中心は、AIやキャラクター単体ではなく、**地域の日常へのアクセス**に置く。主な差別化要素は次の3つ。

- 観光向けの商品ではなく、通常営業中のお店も発見・予約できる。
- 店主の人柄、営業の歴史、常連客、普段の店の様子などから選べる。
- 小規模事業者が普段の営業を変えずに外国人旅行者を受け入れられる。

アプリ側による「ローカル度」の判定や点数付けは行わない。事業者が申告した情報など、利用者が自分で判断できる事実を表示する。

### 世界観【追記】

- 色は **白と赤**。白を基調に、原色に近い明るい赤をアクセント（ロゴ、ボタン、選んだもの）に使う。
- 赤はエラーの色と重なるので、エラーは赤い文字だけにせず、アイコンと文章で伝える【提案】。

## 5. 画面フロー

### 5.1 旅行者画面（~~英語~~ 英語・簡体字・繁体字・韓国語【追記】）

① **入口**：Google検索・マップ、ホテルのQRコードからWebで開く。アプリのダウンロードは不要。閲覧にログインは不要。

②【追記】 **ロゴの画面**
- トップを開くたびに、まずロゴだけの画面を出す。タップすると始まる。
- 【追記】ロゴの後に「旅行者」か「お店の方（事業者）」かを選ぶ。旅行者は③の検索へ、事業者は事業者画面へ進む。旅行者と事業者を1つのアプリにまとめるため。
- Google検索などから店の詳細ページに直接来た人には出さない【提案】。

②の2【追記】 **キャラクターとの会話**
- 「旅行で使う」を選んだとき、ログインしていなければ毎回、キャラクターが話しかける。選択肢をタップして答える。
- 【追記】画面の上3分の2をキャラクター、下3分の1を言葉と選択肢にする。キャラクターは奥からぽてぽて歩いてきて、「こんにちは！」と話しかけ、自己紹介（日本の町に住む小さな恐竜で、地元の人が通うお店を知っている）と、なぜここにいるのか（普段使いのお店を一緒に探し、日本語がわからなくてもお店の人と話せるように手伝う）を話してから、言語・通貨・アカウントの質問に進む。
- 流れ：あいさつ → 言語を選ぶ → 通貨を選ぶ → 「アカウントを作ると、お店の保存・メッセージ・予約ができるよ」とすすめる（アカウントを作る／もう持っている／あとで）。
- どの段階でも「あとで」で飛ばせる。ログインしている人には出さない。

③【追記】 **最初の検索**
- まず **行先・日時・人数** から検索する。
  - 行先：~~エリアの一覧から選ぶ~~ **日本列島のイラストから、地方 → 都道府県 → 市区町村の順にタップして選ぶ**【追記】か、「現在地の近く」を押す。「日本全国」「○○県全部」も選べる【追記】。
  - 日時：日付を選ぶ（時間帯は任意）【提案】。
  - 人数：選択式。
- 初回は表示言語（英語／簡体字／繁体字／韓国語／日本語【追記】。端末の設定から推定）と表示通貨を選ぶ。通貨には「円（JPY）」もあり、円を選ぶと目安の換算は出さない【追記】。あとから右上のメニューの「設定」で変えられる。
- 「地図から探す」ボタンで、地図の画面に切り替えられる（⑤）。

④ **一覧画面**（検索の結果）
- キャラクターが ~~画面上部で~~ **画面の端に小さく出て**【追記】一言あいさつする（固定文）。×で閉じられる【提案】。
- 【追記】キャラクターは一覧だけでなく、旅行者画面のどこにでもいる。画面ごとに一言が変わる（例：詳細では「気になったら店主に聞いてみよう！」）。邪魔ならドラッグで好きな場所に動かせ（場所は端末に保存）、「隠す」で消せる。右上のメニューの「キャラクターを表示」で戻せる。
- 【追記】（2026-10-19）**キャラクターと話せる**。吹き出しの「💬 話す」を押すと、下から会話の画面が出る。
  - よくある質問（予約のしかた・〇△✕ーの意味・支払い・日本語が話せなくても大丈夫か）はボタンで聞け、決まった答えをすぐ返す（AIを使わない）。
  - 自由に書いたことには、Gemini がキャラクターとして、旅行者の言語で1〜3文で答える。話題はアプリの使い方と日本の旅（お店のマナー・支払い・簡単な日本語など）だけ。お店の空き・料金・営業時間などは作らず、検索やお店へのメッセージを案内する。ほかの話題には答えない。
  - ログインしなくても話せる。使いすぎを防ぐため、1人（未ログインはIPごと）10分で20回まで。会話はその画面を開いている間だけ端末に残し、サーバーには保存しない。答えは自動で作っていることを画面に書く。
- 各カードに出すもの：
  - 写真【追記】、店名、カテゴリ、~~エリア~~ 市区町村と都道府県【追記】
  - **値段帯**（例：¥1,000〜3,000、自国通貨の目安も）【追記】
  - **今日から1週間の〇△✕**【追記】（〇＝空きあり、△＝残りわずか、✕＝満席・休み。検索した人数で判定する）
  - **地元のお客さんとその他（観光客・海外から）の割合の帯グラフ**【追記】、営業年数、~~主要駅~~ 最寄り駅【追記】からの距離
  - **タバコ・ペットのマーク**【追記】、**個室の有無**【追記】、**特典あり**の印【追記】
- 絞り込み：カテゴリ、~~エリア~~（行先は③で選ぶ）【追記】、予算（値段帯）【追記】、~~客層~~ 地元のお客さんの割合【追記】、営業年数、~~主要駅~~ 最寄り駅【追記】からの距離（1km以内／3km以内／10km以内）、タバコ・ペット・個室・特典あり【追記】、**選んだ日に空きがある・時間帯（午前／午後／夜）・食事制限への対応・当日予約OK・カード払いOK**【追記】。
- 【追記】絞り込みはアイコン付きのボタンを横一列に並べ、横にスライドして選ぶ。
- 【追記】検索結果の上に為替を出す（例：1 SGD ≈ ¥123）。円を選んでいる人には「自分の国の通貨でも表示する」を出す。
- 【追記】各カードに ♡（保存）を出す。
- 並び順は新着順【提案】。検索した日に空きがある店を先に出す【追記・提案】。おすすめ順は次フェーズ。

⑤【追記】 **地図から探す**
- 【追記】一覧から地図に切り替えたら、検索結果のお店がすべて入るように寄せて表示する。ピンにはお店の種類の絵文字（うどん・そば・ラーメン🍜、寿司🍣、お茶🍵など）を出し、近づくと店名も出す。
- 一覧と同じ条件の店を、地図上にピンで表示する。ピンをタップすると店の概要が出て、詳細に進める。
- 地図を動かして「このあたりで探す」を押すと、見えている範囲の店に絞り込む。
- 「現在地」ボタンで、今いる場所の周りを表示する。位置情報を許可しないときは、~~エリアの一覧~~ 日本列島のイラスト【追記】から選ぶ。

⑥ **詳細ページ**（~~英語に~~ 旅行者が選んだ言語に【追記】自動翻訳）
- 【追記】お店の情報は、色の付いた枠で区切って見せる（地元らしさ＝緑、料金＝赤、空き状況＝青、店主のこだわり＝黄、くわしい情報、場所）。
- 【追記】**空き状況**：今日から2週間の〇△✕を出す。日を押すと、その日の時間枠（何時から何時・残り何名）が出て、「この時間で予約」で予約の画面に進める（日・時間・人数が入った状態）。
- 写真【追記】、説明文、料金（日本円＋目安、現地払い）、値段帯【追記】、所要時間、受け入れ人数、現地での支払い方法（現金のみ／カード可）、住所、地図【追記】、カテゴリ別項目、外部リンク（あれば）。
- **一番人気・店主のおすすめ**（写真・名前・値段・ひとこと）と、**店主のこだわり**（文章・写真）【追記】。
- 【追記】**Google マップで開く**ボタン（登録された位置で開く。スマホではアプリがあればアプリで開く）。
- 【追記】料金の欄に為替（1 SGD ≈ ¥123 など）を出す。
- 【追記】店名の横に ♡（保存）を出す。
- **地元のお客さんの割合**の帯グラフ（「店の申告」と明記）、営業年数、~~主要駅~~ 最寄り駅【追記】からの距離、タバコ・ペット・個室【追記】。
- **このアプリからの予約の特典**（事業者が決めたもの。あれば）【追記】。
- 「質問する（チャット）」と「予約する」の2つのボタン。どちらも押した時点でログインを求める。

⑦ **登録・ログイン**
- メールアドレスとパスワードで登録する。事業者と同じ仕組み。
- 登録時に、名前（事業者に表示）を入れ、利用規約とプライバシーポリシーに同意する。
- 登録やログインが済んだら、押したボタンの画面（チャットか予約）に戻る。
- パスワードを忘れたら、登録したメールアドレスに再設定のリンクを送る。

⑧ **チャット**
- 旅行者は ~~英語で~~ 自分の言語（英語・簡体字・繁体字・韓国語）で【追記】書き、事業者には日本語で届く。事業者の返信は ~~英語に~~ 旅行者の言語に【追記】翻訳して表示する。
- 原文も「原文を見る」で確認できる【提案】。
- 新着メッセージは、~~画面上の未読バッジ~~ 右上のメニューの未読バッジ【追記】で知らせる。メール通知はしない。
- 【追記】**定型文**：よく使う質問（一人でも行けますか？／カードは使えますか？／ベジタリアン向けのメニューはありますか？など7つ）を、旅行者の言語でボタンとして出す。押すと入力欄に入る。定型文には5言語の決まった訳があり、そのまま送れば翻訳APIを使わずに正しく届く。
- 【追記】お店からの返信は、旅行者が今設定している言語で読める。言語を変えたら、開いたときに訳し直す。

⑨ **予約**
- 日付をカレンダーから選ぶ（各日に〇△✕を出す。選んでいる人数で判定）【追記】 → 空きのある時間枠（「10:00〜12:00」のように始まりと終わり）【追記】を選ぶ → 人数を選ぶ。満席の枠、定休日、受付停止日、受付締切を過ぎた日は選べない。最初の検索で選んだ日時と人数を、はじめから入れておく【追記】。
- 食事制限（選択式）と事業者へのメッセージ（任意）を入力する。メッセージは日本語に翻訳して届ける。
- 内容を確認して確定する。カード登録はない。
- 確定画面には、日時、人数、住所、現地で払う金額（日本円＋目安）、**この予約の特典**【追記】を表示する。

⑩ **マイ予約**
- 予約の一覧と、キャンセル。開始時刻までいつでも無料でキャンセルでき、枠は自動で空く【提案】。
- 事業者がキャンセルした予約は、理由（~~英語に~~ 旅行者の言語に【追記】翻訳）と一緒に表示する。
- 予約ごとのチャットに進める。

⑩の2【追記】 **保存したお店**
- 気に入ったお店を ♡ で保存し、右上のメニューの「保存したお店」から後で見返せる。旅程の候補として見返して、予約に進める。
- 保存にはログインが必要。ログインしていなければ ♡ を押すとログイン画面に進み、終わったら元の画面に戻る。

## 6. イレギュラーケース

### ① 空っぽ

- 店舗が1件も登録されていない → 「まだ店舗がありません」と表示する。サンプルの店は出さない。
- 絞り込みなしで一覧を開く → 全店舗を新着順で表示する。
- 最初の検索で行先・日時・人数を選ばずに進む → 日本全国・今日・2名として探す【追記・提案】。
- 日付・時間枠・人数が未選択 → 確定ボタンを押せない。足りない項目を ~~英語で~~ 旅行者の言語で【追記】示す。
- 事業者が必須項目を空のまま保存 → 下書きとして保存し、公開はできない。
- 時間枠を1つも登録していない店舗 → 詳細は公開するが、予約ボタンは出さずチャットのみにする【提案】。
- 写真がない店舗 → カテゴリに合ったイラストを代わりに出す【追記】。

### ② 過剰

- 枠の残り人数を超える人数 → 残り人数までしか選べない。
- 長すぎるメッセージ → 文字数の上限を設け、翻訳APIへの過剰な入力を防ぐ。
- 一人の旅行者が大量に予約する → 同時に持てる未来の予約数を制限する【提案】。
- 絞り込みで0件 → 条件を一つ外した場合の件数を示す。
- ログインの失敗が続く → 一定回数で、しばらくログインできないようにする。
- パスワード再設定を何度も申し込む → 同じメールアドレスへの送信回数を制限する。
- 大きすぎる写真・多すぎる写真 → 送る前に端末で小さくし、枚数に上限を設ける【追記】。

### ③ 悪意

- スクリプトや記号の羅列 → すべての入力をエスケープし、画面や翻訳結果で実行・表示されないようにする。
- 外部リンクに不正なURL → `http://` か `https://` で始まるURLだけ受け付ける。旅行者には、外部サイトに移ることを示して別タブで開く。
- 嫌がらせのメッセージ → 事業者がチャット相手をブロックできる【提案】。
- 架空の店舗登録・誇張 → 公開はすぐにする。運営が新しく公開された店舗を毎日目で確認し、怪しければDBで非公開にする。旅行者側にも「この店舗を報告」ボタンを置く。
- 【追記】不適切な写真 → 報告でき、運営が確認して削除する。

### ④ 中断

- 予約入力の途中で閉じた → 入力内容を端末に残し、次に開いたときに再開できる。
- 予約やチャットの途中でログインを求められた → ログイン後に、元の画面と入力内容に戻る。
- 為替レートの取得に失敗 → 最後に取得したレートと取得日時を表示する。日本円は常に表示する。
- 翻訳に失敗 → 原文を表示し、「翻訳できませんでした」と示す。
- 同じ枠を2人が同時に予約 → 確定時に残り人数を再確認し、後から確定した側には満席と伝える。
- 【追記】位置情報を許可しない・取れない → 日本列島のイラストから選んでもらう。
- 【追記】写真の送信が途中で失敗 → 失敗した写真だけ送り直せる。ほかの入力は消さない。
- 【追記】事業者画面を閉じている・スマホがスリープ中 → 音は鳴らない。次に開いたときに新着として表示する。

### ⑤ 別人

- 日本人や在住外国人が使う → 拒まない。~~旅行者画面の表示は英語のみ。~~ 旅行者画面の表示は英語・簡体字・繁体字・韓国語から選ぶ【追記】。
- 団体や旅行会社が大人数で使う → 枠の上限人数で自然に制限される。
- 事業者の家族が複数端末で使う → 同じアカウントで複数端末のログインを認める。
